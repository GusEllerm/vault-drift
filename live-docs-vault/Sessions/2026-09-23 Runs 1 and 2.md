## D13 and M3/M5 (later the same day)

- **The user reframed the signal (D13):** a flag means "note unedited, code it mentions changed" — deterministic, and true in 100% of flags. Whether the note still reads right is the committing agent's job, at commit. No separate LLM judge; precision becomes an overhead measure; recall, per-commit overhead and coverage are the metrics. The [[Judge]] note is now optional automation.
- **Built** (`2acb820`, follow-ups): `check(refine=False)` — annotation is the default, suppression is a flag; `affected`; the hooks (`read_gate`, `stop_heads_up`, `bypass_log`, `pre_commit`); `install-hooks` (Claude Code settings with fail-closed shell wrappers, `.git/hooks/pre-commit`, `.livedocs/config.json`); `coverage`; mechanical auto-ack at commit for provably benign reports (comment-only, verified moves, class-changed-elsewhere, members-unchanged-without-base).
- **Proven on the testbench** (branch `livedocs-m2`, all git via `git -C`): body edit → commit blocked with was/now for both notes that mention the symbol; `--ack --reason` on each → passes; comment-only edit → auto-acked by pre-commit (`by: pre-commit`, `reason: mechanical: unchanged`) and committed; real change → blocked again. Read gate, Stop heads-up (and its `stop_hook_active` short-circuit), bypass log, drift-missing → `unknown`, import-crash → shell fallback all exercised through stdin as Claude Code would call them.
- **Fixed during the proof:** dangling warnings were noise (SSH option names are CamelCase); "dangling" now means a mention that resolved in the note's previous stamp and no longer does, or a snake_case/call identifier. Pre-commit output omits warnings; the read gate caps them at three.
- **Coverage on hpc-bridge at HEAD:** 3,317 of 6,814 mentions anchored (49%); Modules/ notes 70–89%; `shapes.md` 18% (constants).

## Harness discussion and D14

The user's principle: the guarantee is a mechanism of the development framework (git), not a skill of the agent; channels 1 (the failed commit's output) and 2 (the Stop heads-up) over 3 (an instruction the agent follows). Recorded as D14 with the four tiers.

## Constant anchors and the live hook test

- **P24 implemented:** a constant binds its file with drift and carries its own member hash. On `shapes.md`, changing `_SLURM_TEMPLATE`'s value flags `changed(body)` with was/now; an unrelated edit in `remote.py` annotates both constants as unchanged (benign). End-to-end test `tests/test_stamp_check.py` (skips without drift).
- **Live Claude Code test** (headless `claude -p`, Sonnet, four sessions in the testbench with all hooks installed via `livedocs init --read-gate --bypass-log`; `livedocs` on PATH via `uv tool install --editable`):
  1. Read gate: the model received the LIVE-DOCS report with the file and repeated it verbatim.
  2. Stop heads-up: fired after an edit to a mentioned symbol; the model received the affected-notes list.
  3. **Subagents are covered:** a general-purpose subagent's `Read` triggered the gate and the subagent saw the report.
  4. Bypass: a `head` via Bash was logged to `bypass.jsonl`; the agent saw nothing.
  Cost: about $0.50 for the four sessions.
- Fix: the heads-up now labels members-unchanged reports as benign instead of printing `CHANGED … (unchanged)`.
